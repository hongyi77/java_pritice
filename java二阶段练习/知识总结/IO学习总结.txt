Java IO 学习总结
==================

一、你已经掌握的内容
---------------------

1. 字节流基础
   - FileInputStream / FileOutputStream：从文件读取字节、向文件写入字节
   - 基本读写循环：fis.read() 返回 -1 表示读完
   - 缓冲区优化：byte[] buffer，每次读取一块而非逐字节

2. 手动资源管理
   - fis.close() / fos.close() 释放系统资源

3. 性能测量
   - System.currentTimeMillis() 记录时间差，评估代码耗时

4. 缓冲区大小的理解
   - 8192 表示 8KB，每次读写一块数据，减少磁盘 I/O 次数
   - 太小效率低，太大浪费内存，折中取 4KB~64KB

二、你还需要学习的内容
-----------------------

1. try-with-resources（重要）
   自动关闭资源，不需要手动写 close()，即使发生异常也能安全关闭：

   FileInputStream fis = new FileInputStream("path");
   FileOutputStream fos = new FileOutputStream("path2");
   try (fis; fos) {
       // 读写操作
   } // 这里自动关闭，不用手动 fos.close()

2. 字符流（处理文本）
   字节流处理的是原始字节，适合图片/视频等二进制文件。
   文本文件应该用字符流，自动处理编码（UTF-8、GBK 等）：

   - FileReader / FileWriter：读写字符文件
   - BufferedReader / BufferedWriter：带缓冲区的字符流，效率高
   - BufferedReader.readLine()：按行读取，非常方便

3. 装饰器模式 / 节点流与处理流
   Java IO 的核心设计思想：
   - 节点流（Node Stream）：直接连接数据源，如 FileInputStream
   - 处理流（Processing Stream）：包裹节点流，增强功能，如 BufferedInputStream
   就像套娃一样，一层一层加功能：
   new BufferedInputStream(new FileInputStream("file"))

4. BufferedInputStream / BufferedOutputStream
   比手写 byte[] 更简洁的缓冲方式：

   BufferedInputStream bis = new BufferedInputStream(fis);
   BufferedOutputStream bos = new FileOutputStream("out");
   int b;
   while ((b = bis.read()) != -1) {
       bos.write(b);
   }

5. RandomAccessFile
   支持随机读写，可以跳到文件的任意位置操作：

   RandomAccessFile raf = new RandomAccessFile("file", "rw");
   raf.seek(100);    // 跳到第 100 字节
   raf.writeInt(42); // 写入整数
   raf.close();

6. NIO（java.nio.file）— 现代 Java 推荐方式
   简化了文件操作，一行搞定拷贝：

   import java.nio.file.Files;
   Files.copy(Paths.get("源路径"), Paths.get("目标路径"));

   其他常用 NIO 功能：
   - Files.exists(path)：检查文件是否存在
   - Files.delete(path)：删除文件
   - Files.size(path)：获取文件大小
   - Files.readAllBytes(path)：一次性读取全部字节
   - Files.write(path, bytes)：一次性写出全部字节
   - Files.walkFileTree(path)：遍历目录树

7. Scanner / BufferedReader（读取用户输入或文本）
   - Scanner：方便解析各种数据类型（nextInt、nextLine 等）
   - BufferedReader：读取速度快，适合大量文本

8. 管道流（PipedInputStream / PipedOutputStream）
   用于线程间通信，一个线程的输出作为另一个线程的输入。

9. 对象序列化（Serializable）
   把对象直接保存到文件，或通过网络传输：

   ObjectOutputStream oos = new ObjectOutputStream(fos);
   oos.writeObject(myObject);

   ObjectInputStream ois = new ObjectInputStream(fis);
   MyClass obj = (MyClass) ois.readObject();

三、字节流 vs 字符流 对比
--------------------------

|          | 字节流              | 字符流              |
|----------|--------------------|--------------------|
| 基类     | InputStream/OutputStream | Reader/Writer    |
| 用途     | 图片、视频、音频等二进制文件 | 文本文件           |
| 例子     | FileInputStream    | FileReader         |
| 编码处理 | 不处理，原始字节     | 自动处理编码        |
| 建议     | 不确定就用字节流     | 处理文本一定用字符流 |

四、学习建议
------------

1. 先掌握 try-with-resources，这是必须养成的习惯
2. 学会 BufferedReader + InputStreamReader 组合，处理文本很常用
3. 了解 NIO 的 Files.copy，实际开发中文件拷贝基本就这么干
4. RandomAccessFile 面试常考，理解 seek() 的原理
5. 装饰器模式是 Java IO 的设计精髓，理解了就一通百通

五、常见面试考点
----------------

1. BIO（阻塞式 IO）vs NIO（非阻塞式 IO）的区别
   【答案】
   - BIO（java.io）：同步阻塞，每个连接需要一个独立线程处理，读/写操作会阻塞线程直到完成。线程消耗大，不适合高并发。
   - NIO（java.nio）：同步非阻塞，三大核心：Channel（通道）、Buffer（缓冲区）、Selector（选择器）。一个线程可以通过 Selector 多路复用管理成千上万个 Channel，适合高并发场景（如 Netty 底层就是 NIO）。
   - 关键区别：BIO 是流式，NIO 是面向缓冲区/通道的；BIO 一个连接一个线程，NIO 一个线程可以管多个连接。

2. 字符流和字节流的选择场景
   【答案】
   - 字节流：处理任何类型的文件（图片、视频、音频、PDF 等二进制文件），以及网络传输的原始数据。不会进行编码转换。
   - 字符流：专门处理文本文件（.txt、.java、.xml 等），会自动根据编码表（UTF-8、GBK）转换字符。如果用字节流读中文文本，遇到多字节字符（UTF-8 中文占 3 字节）可能截断导致乱码。
   - 原则：不确定就用字节流（万能），处理文本一定用字符流。

3. try-with-resources 的原理（AutoCloseable 接口）
   【答案】
   - Java 7 引入，实现了 AutoCloseable 接口的资源可以在 try() 中声明，JVM 会在 try 块结束后（无论是否发生异常）自动调用 close() 释放资源。
   - 原理：编译器会把 try-with-resources 翻译成 try-catch-finally，在 finally 里调用 close()。如果 try 块和 close() 都抛了异常，try 块的异常是主异常，close() 的异常会被抑制（通过 getSuppressed() 获取）。
   - 好处：代码简洁，不会忘记关闭资源，异常处理更安全。
   - 示例：
     try (FileInputStream fis = new FileInputStream("file")) {
         // 使用 fis
     } // 自动关闭

4. Buffer 的三个属性：position、limit、capacity
   【答案】
   - capacity：缓冲区的最大容量，创建后不可变。
   - position：下一个要读/写的字节位置。写入时 position 递增，调用 flip() 后会重置为 0。
   - limit：能读/写的边界。写入时 limit = capacity；调用 flip() 后 limit = position，position = 0，准备读取。
   - 典型流程（写入再读取）：
     1. buf.put(data)    // position 递增，写入数据
     2. buf.flip()       // limit=position, position=0，切换到读取模式
     3. buf.get()        // 从 position 读到 limit
     4. buf.clear()      // position=0, limit=capacity，清空准备下次写入
   - 面试常考：flip() 和 clear() 的区别，position 和 limit 的变化。

5. 序列化时 transient 关键字的作用
   【答案】
   - transient 修饰的字段不会被序列化，保存时会用默认值代替。
   - 用途：保护敏感信息（如密码），或者字段可以由其他字段推导出来无需保存（如缓存的计算结果）。
   - 示例：
     private String username;
     private transient String password; // 不会被序列化
   - 反序列化后 password 会是 null（引用类型默认值）。
   - 注意：实现 Serializable 接口才能序列化，JDK 1.1 起推荐 writeObject/readObject 自定义序列化逻辑。

6. Files.walkFileTree 遍历文件的实际应用
   【答案】
   - Files.walkFileTree(path, visitor) 可以递归遍历目录树，比简单的 listFiles() 强大得多。
   - 核心是 FileVisitor 接口，有四个回调方法：
     - preVisitDirectory：进入目录前调用
     - visitDirectory：成功进入目录后调用
     - visitFile：遍历到文件时调用
     - postVisitDirectory：离开目录后调用
   - 实际应用场景：
     - 查找并删除所有 .tmp 临时文件
     - 统计某个目录下每种扩展名文件的数量
     - 批量替换文件中某段文本内容
     - 搜索包含特定内容的文件
   - 示例（查找所有 .java 文件）：
     Files.walkFileTree(startDir, new SimpleFileVisitor<Path>() {
         @Override
         public FileVisitResult visitFile(Path file, BasicFileAttributes attrs) {
             if (file.toString().endsWith(".java")) {
                 System.out.println(file);
             }
             return FileVisitResult.CONTINUE; // 继续遍历
         }
     });
   - 返回值含义：CONTINUE（继续遍历）、TERMINATE（停止遍历）、SKIP_SIBLINGS（跳过同级）、SKIP_SUBTREE（跳过子目录）。
